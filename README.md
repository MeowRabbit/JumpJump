# 산책훈련 <sub>(원제 JumpJump)</sub>

게임 엔진을 쓰지 않고 **C++와 WinAPI만으로 만든 2D 플랫포머**입니다.
발판을 밟고 위로 오르는 수직 등반형 게임이며, 기획부터 구현까지 **1인 20일**에 완성했습니다.

> 상업적 완성도보다 **짧은 기간 안에 한 편을 처음부터 끝까지 스스로 끝내는 경험**을 목표로 잡았습니다.
> 렌더 루프, 충돌 판정, 오브젝트 수명 관리를 직접 짜면서 엔진이 대신 해주던 일이 무엇인지 확인하는 것이 목적이었습니다.

## 소스 구성

```
JumpJump.sln
JumpJump/
├── Main.cpp            윈도우 생성, 메시지 루프, 진입점
├── GameSystem.cpp/h    게임 루프 전반 — 시점 스크롤, 스폰, 점수, 화면 전환, 렌더
├── Player.cpp/h        이동·점프·착지, 가속도 처리, 충돌 판정
├── Ground.cpp/h        발판 생성과 회수
├── Item.cpp/h          아이템 생성·획득·효과 적용
├── Trap.cpp/h          함정 생성과 판정
├── Upgrade.cpp/h       업그레이드 상점, 구매 처리
├── Font.cpp/h          비트맵 폰트 출력
├── Public.cpp/h        공용 유틸리티
├── Object.h            (빈 파일 — 아래 '알려진 한계' 참조)
└── JumpJump.rc         비트맵·아이콘 리소스 정의
```

`GameSystem.cpp`가 약 41KB로 가장 큽니다. 게임 루프와 렌더가 이 파일에 모여 있습니다.

## 구현한 것

- **렌더** — 더블버퍼링, 스프라이트 블리팅, 시점(뷰포트) 스크롤
- **물리** — 가속도 기반 이동·점프·착지, AABB 충돌 판정에 경계 보간 도입
- **스폰** — 땅 · 아이템 · 함정 랜덤 생성, 화면 밖으로 벗어난 오브젝트 회수 후 재사용
- **자원 관리** — 고정 배열 재사용으로 오브젝트 수명 관리, 사용이 끝난 자원 즉시 반환
- **메타** — 점수, 업그레이드 상점, 최고기록 파일 저장, 게임오버·리트라이

화면은 시작 → 로비 → 게임 → 종료 4단계이고,
데이터 구조는 캐릭터 · 땅 · 아이템 · 함정 · 업그레이드 5종으로 설계했습니다.

## 해결한 문제

### 1. 조작이 뚝뚝 끊긴다

이동값이 **정수 픽셀 고정**이라 캐릭터 크기와 맞지 않는 단위로 튀었고, 프레임도 초당 12로 묶여 있었습니다.

화면에 그리는 정수 좌표와 별도로 **내부에 실수 좌표 공간**을 두어 소수점 단위로 누적하고,
이동에 가속도를 적용한 뒤 최대 속도로 클램프했습니다. 지상과 공중의 가속을 다르게 줬습니다.

→ **12fps → 60fps**

### 2. 첫 점프로 닿을 수 없는 곳에 발판이 생긴다

발판 생성 좌표가 완전 랜덤이라, 시작 직후 도달 불가능한 위치에 발판이 잡히면 즉시 게임오버였습니다.

기본 이동력과 점프력으로 **실제 도달 가능한 거리**를 계산하고,
이전 땅을 기준으로 그 범위 안에서만 랜덤값이 나오도록 제한했습니다.

### 3. 빠르게 떨어지면 땅을 뚫고 추락한다 (터널링)

낙하 속도가 커지면 **이전 프레임과 다음 프레임의 높이 차가 땅 두께를 넘어서**,
두 프레임 모두 땅 바깥에 있어 충돌 판정 자체를 건너뛰었습니다.
높은 곳에서 떨어져 중력 가속도가 클수록 재현율이 올라갔습니다.

충돌을 매 프레임의 *위치*가 아니라 프레임 사이의 *구간*으로 판정하도록 바꿨습니다.
플레이어 아래에 **다음 착지 지점을 나타내는 그림자**를 두고, 프레임 갱신 시 플레이어가 그림자를
지나쳤는지 검사해 지나쳤으면 그림자 위치로 되돌립니다.
그림자는 화면에도 그려, 판정 기준인 동시에 착지 지점을 미리 보여주는 장치가 됩니다.

→ **땅 관통률 27% → 0%**

## 측정 결과

| 항목 | 최초 | 1차 수정 | 최종 |
|---|---|---|---|
| 땅 관통률 | 27% | 7% | **0%** |
| 프레임 | 12 fps | 60 fps | **60 fps** |
| 평균 점수 | 0.8천 | 2.2천 | 1.5천 |
| 평균 플레이 시간 | 5.7분 | 5.8분 | 4.7분 |

최종에서 점수와 플레이 시간이 내려간 것은 **의도한 조정**입니다.
1회 플레이 **5분**을 목표로 잡았는데 1차 수정 후 5.8분으로 목표를 넘어서,
장애물 수를 늘리고 회복 아이템 등장 확률을 낮춰 4.7분으로 맞췄습니다.
점수는 플레이 시간에 비례하는 구조라 함께 내려갔습니다.

## 알려진 한계

숨기지 않고 적습니다.

- **절차지향 구조.** 클래스가 아니라 `struct` + 자유 함수로 되어 있습니다.
  (`typedef struct _OBJ_Player { ... } OBJ_Player;` / `void Move_Player(HWND, OBJ_Player&);`)
- **전역 상태.** `GameSystem.h`에 `extern` 전역 변수가 30개 이상 있습니다.
- **`Object.h`가 빈 파일입니다.** 공통 오브젝트 추상화를 시도했다가 끝내지 못한 흔적입니다.
- **`GameSystem.cpp` 비대.** 게임 루프와 렌더가 한 파일에 몰려 있습니다.

모듈 분리(Player / Ground / Item / Trap / Upgrade / Font)와 주요 필드 주석은 되어 있습니다.
